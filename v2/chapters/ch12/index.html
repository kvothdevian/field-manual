Briefing · 5 min · the doorway, not willpower

i.Pipelines that prevent bloat in one paragraph

Rot is the default: every session leaves a debug print, a copied helper, a comment blob that made sense at midnight, and agents copy that drift forward as fact. Willpower never removes it — a doorway does. A gate is automatic (it runs without being asked), binary (exit 0 opens, anything else blocks), and fast (seconds, so it runs every time). Put three such gates between the branch and the merge and bloat stops being a character flaw and starts being a rejected change.

The three local gates run cheapest first. Correctness asks whether the code ever ran: a syntax check plus a smoke run rejects never-executed files before anything else spends a second on them. Hygiene scans for debris the author already knows is debris — stray prints, TODO markers, a helper defined twice, a run of comment lines nobody will read. Size enforces a byte budget: the file must fit the allowance, so growth needs a reason, not just a keyboard. Order matters because each gate is cheaper than the next, and a change that fails early never pays for the later checks.

Then the calendar lesson. A doorway judges a change: each merge attempt passes or fails on its own. A calendar judges time: a weekly sweep re-runs the full net over everything, catching what the doorway missed and confirming what it caught. Some six-week stretches the sweep catches nothing — quiet seasons where the net costs more than it lands. That is normal, judged over the long run, not the week. The incubator in step 4 shows both nets side by side so you can feel the difference before you pay for either.

Where it breaks down: unread gates train bypass — a gate whose failure nobody reads becomes a hurdle to jump rather than a verdict to respect, and the permissions docs for major harnesses describe deny-before-ask ordering plus candid bypass caveats for exactly this reason. Uncapped autonomy burns budget: an agent allowed to retry forever against a red gate spends real money re-proving a verdict. No gate judges taste — duplicated structure that passes all three gates is still your call. Accountability stays human: the gate reports, you decide.

ii.A gate is a doorway with an exit code · automatic, binary, fast

Every gate in this chapter speaks the same contract the workflow runners use at scale: the runner reports each step as fail or succeed based on its exit code, so a nonzero exit blocks the chain and zero opens it. Your local check.js is the same idea at desk scale — one script, three verdicts, one number out. Automatic means no human remembers to run it; binary means no human interprets it; fast means no human resents it. Miss any one of the three and the gate quietly stops being run, read, or trusted.

The side lane matters as much as the gates. Doorway gates judge the change in front of them; they cannot judge drift that arrived before they existed, or debris that passes every check by being valid. The weekly sweep — the same workflow file with a schedule arm instead of a merge arm — re-runs the full net over merged code on the clock. Same gates, different trigger: one fires at merge, the other fires on time.

iii.Three gates, cheapest first · the correctness / hygiene / size trio

Correctness is the floor: node --check parses the file without running it, which sounds thin until you watch an agent session end with a file nobody executed. Syntax-verified is not behavior-verified — the gate proves the file loads, nothing more — but unparseable code wastes every later check, so it runs first. Hygiene is the scan for things the author already agrees are debris: a console.log left from debugging, a TODO that moved in permanently, a helper defined twice after a copy, six comment lines in a row explaining what the code already says. Each pattern is named in the failure line, so the fix is a deletion, not an investigation.

GATE 2 ✓hygiene — catches prints, dupes, blobs (illustrative)

Size is the budget with teeth: 800 bytes for the whole file in this session, a number picked so the clean baseline (317 bytes) passes with room and the seeded bloat (815 bytes) fails. The byte count is arbitrary; the mechanism is the point. Growth must arrive as a deliberate budget change, visible in the diff, instead of eleven quiet lines per session that nobody totals. When the file legitimately outgrows the allowance, you raise the number in writing — which is itself a review of what the file became.

iv.Doorway vs calendar · what fires at merge, what needs a clock

The doorway and the calendar answer different questions, and confusing them is the standard failure. The doorway asks "may this change land?" — it fires on every merge attempt, judges only the diff, and forgets everything after. The calendar asks "what did we miss?" — it fires on schedule whether or not anything changed, judges the whole tree, and remembers across weeks. A team with only a doorway accumulates valid-but-rotten code; a team with only a calendar argues about ancient debris with no change to attach the fix to. You need the doorway to stop the bleeding and the calendar to find the bruises.

Quiet seasons are the calendar's honesty mechanism. A sweep that catches nothing for six weeks looks like waste until the seventh week lands a duplicate helper three sessions old. Judge the net over the long run: log catches per week, label the zeroes "quiet" instead of "broken," and only retire a sweep after a long quiet you can point at. The bypass warning from the briefing returns here — an unread gate trains jumping, and an unread sweep trains exactly the same habit at a slower cadence. Read the red, or delete the gate.

1.Build the gate

Goal: the agent writes check.js only; you run it and watch exit 0 on the clean 317-byte baseline. app.js stays untouched.

Create check.js in this directory (plain node, no installs). It runs three gates over app.js, cheapest first, and exits 0 only if all pass: GATE correctness — run `node --check app.js`; on failure print FAIL [correctness] plus the error. GATE hygiene — scan the app.js text for console.log, TODO or FIXME, a duplicated helper (the identifier total defined or assigned more than once), and a comment blob (6 or more consecutive // lines); on any hit print FAIL [hygiene] naming the pattern found. GATE size — fail if app.js exceeds 800 bytes, printing FAIL [size] with the byte count. On success print PASS lines and GATE GREEN. On any failure print GATE RED and exit 1. Do not modify app.js.
