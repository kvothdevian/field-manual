Session 13 · shipping for $0 · opencode default

A URL tonight beats localhost forever

Put a static site on a public URL for $0: run a three-check gate, fit the host's first wall on paper, and file a dated readiness card — previews first, production only on green.

60 min · scratch repo ship-lab · book-only, no accounts · verified 2026-09-04

Briefing · 5 min · a link you can send

i.Shipping for $0 in one paragraph

A localhost demo dies with your laptop lid; a public URL keeps working while you sleep and forces the agent's output to meet the real network. Tonight's move is small on purpose: one static folder, one free host, one link you can text to a friend. The stakes are not traffic — the toy gets none — they are the habit. Every later project inherits the ritual you set here: preview before production, gate before push, card before claims.

The ritual itself is vendor-free and fits in one sentence: a static folder goes into git, git connects to a host once, and from then on every push is a deploy. Branch previews give you a disposable URL per change, so review happens on the live artifact. Merge to the main branch and production updates. No server to feed, no pipeline to babysit at this scale — the host watches the branch and rebuilds. Learn the shape once and all four hosts below feel familiar, because the shape is the product.

Two wall species guard the $0 tier, and they warn you differently. Numeric walls are meters: builds per month, bandwidth per month, credits per deploy. They trip silently — the 501st build simply does not run, and nobody emails you. Legal walls are clauses: the terms bar commercial hosting and SaaS storefronts on a free showcase tier. Clauses have no meter; enforcement arrives as an email or a disabled site. Read the meter for the first species and the terms page for the second, because each wall is invisible to the other's instrument.

Under an agent, the $0 budget needs writing down, because an agent treats deploys as free keystrokes. The card carries three lines: N production deploys allowed, previews-first as the default lane, and a stop line naming what halts the run. Previews are the free rehearsal — unlimited on three of the four hosts below — so the agent can burn twenty preview URLs learning and still cost nothing. Production is the metered lane. State the number before the run, and the agent spends against a budget instead of against your surprise.

Gate before push, card after. The pre-publish gate runs locally with no account and checks three things: every link resolves, the weight fits the published wall, and no secret-shaped string ships in the folder. Red means fix, green means you may merge. The card then records the decision: host, numeric first-wall, as-of date, and the constraining terms line. Where this breaks down: static hosts serve files only; free numbers move silently, so re-stamp figures quarterly; and silence about a limit is hope, not architecture — write UNPINNED where the page names no number, never infinity.

ii.Two wall species · meters trip silently, clauses arrive by email

Keep the species apart and each gets the right instrument. A numeric wall answers "how much" — builds, files, megabytes, credits — and you watch it on a dashboard or compute it on paper before you push. A legal wall answers "what for" — showcase projects yes, storefronts no — and you read it on the terms page, because no dashboard will ever show it. The classic failure swaps the instruments: the builder who reads the terms for a bandwidth number that lives only on the limits page, or the builder who watches a usage graph for a commercial-use clause that lives only in the contract. Name the species first, then pick the instrument.

The previews-first arrow is the whole budget strategy in one glyph. Every host below except one hands out branch previews outside the production meter — unlimited on Cloudflare, Netlify, and Vercel's lane — so the agent's trial-and-error happens where trial is free. Production merges are the only moves that spend: a build off the monthly quota, bytes off the bandwidth allowance, credits off the refill. Count production deploys the way you count anything scarce, and let previews absorb everything else. The readiness card in step 4 is where that count becomes a promise.

iii.The ritual, once · folder → git → connect-once

Seven nodes, one connection step, and only the last two spend money-that-isn't-money. The folder holds plain files; git gives the folder a memory; connect-once ties a branch to the host in the dashboard — the single step this book labels docs-only, because no account is opened in this session and the card records intent, not a live hookup. From there the loop is mechanical: push a branch, open its preview URL, review the artifact, merge, and watch production update. Teach the loop with the toy and it transfers to every static host unchanged, because the differences between hosts live in the walls, never in the ritual.

1folder · index.html + 2 pages
2git · baseline commit
3connect-once · docs-only badge ⛔ no account opened
4preview · per-branch URL, free rehearsal
5review · on the artifact, not screenshots
6merge · spends builds/bytes/credits ◉
7production · the URL you can text ◉

The meter marks sit on nodes 6 and 7 only, and that placement is the discipline. Everything left of merge is rehearsal: broken links, ugly spacing, and agent experiments all happen on preview URLs that cost nothing and vanish when the branch does. A red gate blocks node 6 — never node 4 — because a broken preview is information while a broken production URL is a promise kept badly. When the agent asks to "just push and see," point at the timeline: seeing happens at node 4, spending happens at node 6, and the two are different verbs.

iv.Gate before push · local, no account, three checks

The gate is a small authored script, not a service: it reads the folder, resolves every local link, weighs the heaviest file against the published wall, and scans shipped files for secret-shaped strings. It runs with plain node, exits 1 red and 0 green, and knows nothing about hosts, accounts, or networks — which is exactly why you can trust it. Three checks, each with a shape-plus-label verdict, because a gate that prints "done" without naming what it checked is a costume. The strip below is the step-1 expectation and the step-2 target in one glance.

LINKS ✕ 1/2step 1: guide.html missing — RED blocks merge
WEIGHT ✓ 2,153Bheaviest file vs 25 MiB published wall
SECRETS ✓ 0 hitsno key-shaped strings in shipped files
GATE ⬛ RED→GREENexit 1 → exit 0, reader keystrokes only

Each check maps to one wall species or one classic leak. Links resolve because a shipped 404 is the cheapest broken promise in the book, and the seed guarantees you feel the red before you earn the green. Weight fits the published wall because the single-file cap is the wall a toy hits first if it ever grows teeth — images, fonts, video — and the gate quotes the wall's number, not a guess. Secret-shaped strings get scanned because the push-to-URL ritual makes everything in the folder public by construction; the scan's patterns are cross-cited to the deny rules in the security and configuration sessions, so the gate enforces what those chapters teach. Authored, labeled, local: gate.mjs stays authored-labeled in this book, a teaching instrument rather than a cited source.

v.First walls, side by side · numbers live here only

Four hosts, one toy weighing 601 bytes across three pages, re-fetched live and stamped 2026-09-04. Read the "bites first" column for your own weight: at toy scale every host fits with room to spare, so the binding constraint is behavior — builds per hour, credits per deploy, previews or none — not bytes. Where a cited page names no number, the cell says UNPINNED, never infinity: an unwritten limit is a limit you have not found yet, and the card re-stamps quarterly because free numbers move silently.

Two readings deserve emphasis. First, GitHub Pages carries the heaviest legal load in the quad: the terms bar running an online business, e-commerce, or SaaS on the free lane, while explicitly permitting donation buttons and crowdfunding links — so a tip-jar portfolio fits and a store does not, and the card records which side the project falls on. Second, Netlify's credit arithmetic is the tightest numeric wall here: 300 credits divided by 15 per production deploy is 20 production pushes per refill, which makes the previews-first rule load-bearing rather than decorative. The recompute in step 3 runs this division with the reader's own keystrokes, because a wall you have not computed yourself is a rumor.
