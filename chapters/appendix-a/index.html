§ opencode

opencode — the $0 switchboard

opencode

Anomaly · MIT · ~201k ★ · TUI · desktop (beta) · IDE MIT$0 via local or sub reuse

Free OSS binary that speaks to 75+ providers through the Vercel AI SDK + Models.dev, plus local runtimes. Plan (read-only, Tab) and Build agents; skills load on demand; plugins hook lifecycle; LSP with 30+ servers ships off — lsp: true opts in.

install — pick one channel

curl -fsSL https://opencode.ai/install | bash
# verify
opencode --version
npm i -g opencode-ai
# or: brew install anomalyco/tap/opencode
# or: scoop / choco / pacman / docker — see opencode.ai/docs

launch

opencode              # TUI in current repo
opencode run "explain what this folder contains"
opencode --help       # lists /sessions /new /undo /redo /share

config files

opencode.json                 # project or ~/.config/opencode/opencode.json
.opencode/skills/hello/SKILL.md   # skills load on demand; also reads .claude/.agents compat paths
.opencode/plugins/*.ts            # hooks: tool.execute.* / session.* / lsp.*
# lsp opt-in (docs note lint CLIs can be cheaper):
{ "lsp": true }

model wiring

# local — no keys, no billing
opencode  # → pick ollama / lmstudio / llama.cpp provider in setup

# cloud — free-key clouds or reuse what you pay for elsewhere
# ChatGPT Plus/Pro OAuth · GitHub Copilot device-flow · GitLab Duo OAuth
# optional paid: OpenCode Zen / Go — never required
actioncommand / wherewhat to check
switch agentTab in TUI — plan (read-only) ↔ buildstatus bar shows mode; plan refuses edits
sessions/sessions · /new · /undo /redo (git-backed)git log after undo shows reversal
share/share (opt-in link)link appears only after you run it — not automatic
skill invoketype skill name or /skillskill file appears in transcript header
permissionswildcard allow / ask / deny in skill frontmatterdeny test: blocked tool returns denial reason
$0 path — point opencode at Ollama/LM Studio locally → $0 forever; or sign in with an existing ChatGPT / Copilot / GitLab Duo sub you already pay for. Zen/Go are optional. Grey flag: community Claude Pro/Max proxies were removed in v1.3.0 — any revival is a ToS violation.
warning

Plugins are code that runs at startup — vet npm plugins like any dependency. LSP off-by-default is load-bearing: measure lint-CLI cost before enabling lsp: true.

§ claude code

Claude Code — the reference bar

Claude Code

Anthropic · proprietary · terminal / IDE / desktop / web proprietaryno free tier

This is the harness whose best-practices page is the book's content bar. Two constraints drive its advice: context fills fast and performance degrades as it fills — so explore → plan → implement, manage context aggressively, and give Claude a deterministic check it can run.

install & launch

npm i -g @anthropic-ai/claude-code
claude --version
claude                          # in a repo
claude --permission-mode plan   # start read-only
claude -p "explain what this project does"  # non-interactive

verify loop (the bar's core)

# give it a check it can iterate against — never "looks done"
# prompt template:
# "write a validateEmail function. cases: user@example.com true,
#  invalid false, user@.com false. run the tests after implementing"

config files

CLAUDE.md                     # loaded every session — keep short or it gets ignored
.claude/settings.json         # permissions, hooks, sandbox
.claude/skills/*/SKILL.md     # domain knowledge, loaded on demand
.claude/agents/*.md           # subagents — own context window
# check loaded: /context  ·  propose cuts: /doctor

gating escalation ladder

# cheapest → most deterministic
# 1. in one prompt:  "run the check and iterate until it passes"
# 2. across session: /goal — evaluator re-checks every turn
# 3. stop hook:      blocks turn end until script passes (8-block cap)
# 4. subagent review: fresh context refutes the result
patterncommand / ritualwhen
explore→plan→implementShift+Tab plan mode → /plan → Ctrl+G edit plan → approve → implement → commitmulti-file or unfamiliar code; skip for one-line fixes
context hygiene/clear between unrelated tasks; /compact Focus on API changes; /btw for side questionscontext > 50% or after two failed corrections
permissions/permissions allowlist; /sandbox; auto vs manual modePro/Max/Team start in auto (classifier); others start manual
subagent researchuse subagents to investigate X — isolated context windowany investigation that would bloat main transcript
adversarial review/code-review skill or manual: "review diff against PLAN.md in a subagent"before merge; tell reviewer to flag correctness only
resumeclaude --continue · claude --resume · /rename + /rewind (Esc Esc)multi-sitting work; each workstream = own persistent session
$0 path — none honest. Requires active Anthropic subscription or metered API credits. Do not chase community proxies — treat any as ToS breach.
tip

Run /init for a starter CLAUDE.md, then prune. If Claude keeps ignoring a rule, the file is too long. Checks belong in hooks, not prose — hooks are deterministic, prose is advisory.

§ codex cli

Codex CLI — OpenAI's open shell

Codex CLI

OpenAI · Apache-2.0 · CLI · IDE · app · Web cloud Apache-2.0install free · sub or API to run

Same agent routed through every surface — terminal, editor, desktop app and OpenAI's cloud. Open-source core, ~118k ★.

install

npm i -g @openai/codex
codex --version
codex              # sign in with ChatGPT Plus/Pro or API key

config

~/.codex/config.toml        # auth, model, approval mode
# sign-in: ChatGPT OAuth (Plus/Pro) or OPENAI_API_KEY

model wiring

ChatGPT-plan sign-in rides your existing sub; or drop an OPENAI_API_KEY for metered API. Models are OpenAI-hosted.

why this one

Hand the same session to cloud when you leave the desk — continuity across CLI → IDE → web without re-explaining.

$0 path — binary is free; execution needs a paid ChatGPT sub or API billing. No standalone free tier.
§ gemini cli

Gemini CLI — the free door

Gemini CLI

Google · Apache-2.0 · 1M context · checkpointing · MCP Apache-2.060/min · 1 000/day free

The honest $0 harness. Personal Google OAuth unlocks the gratis tier on Gemini models — largest free allowance in the landscape, with a million-token window.

install & auth

npm i -g @google/gemini-cli
gemini --version
gemini                 # first run → personal Google OAuth
# quota: 60 req/min, 1 000 req/day on free OAuth

common commands

gemini --help
/checkpoint            # save/restore — MCP + checkpointing are first-class
/permissions           # allowlist edits

config

~/.gemini/settings.json
.gemini/               # project settings
# model override via settings or GEMINI_API_KEY
$0 path — sign in with a personal Google account — OAuth is the unlock. No billing, no keys for the gratis tier. Keep requests inside 60/min & 1 000/day.

when to reach for it

First harness for a student, or second harness when your paid quota is tapped. Huge context + checkpointing reward long explorations.

§ aider

Aider — git-native pair programming

Aider

Apache-2.0 · pair programmer · auto-commits · repo map Apache-2.0OSS · BYO keys

The most deliberate harness: edits land as git commits you review, with a "repo map" that feeds relevant context without dumping every file.

install

pip install aider-chat
# or: pipx install aider-chat
aider --version
# needs git repo: git init if none

run

aider                           # auto-detects git repo
aider --model ollama/qwen2.5-coder:7b   # local via Ollama
aider --model openrouter/anthropic/claude-3.5-sonnet
# Copilot auth: aider --model github/copilot-claude

config & model wiring

.aider.conf.yml              # per-project
~/.aider.conf.yml            # global
.env  → OPENAI_API_KEY etc.  # keys via env
# edit format leaderboards choose fastest model for your stack

verify

git log --oneline -5       # aider auto-commits — read them
git diff HEAD~1             # the real verification gate
# toggle auto-commits off: aider --no-auto-commits
$0 path — OSS binary + Ollama local, OpenRouter free models, or Copilot auth reuse. No hosted free lunch — you supply the model.

§ pi

Pi — the anti-harness

Pi

Mario Zechner · MIT · @mariozechner/pi-coding-agent · 4 tools MITOSS · BYO keys

Deliberately minimal: four built-ins — read, write, edit, bash. No baked-in subagents, no plan mode. You add ceremony via TypeScript extensions in .pi/extensions/.

install & run

npm i -g @mariozechner/pi-coding-agent
pi --version
pi                          # in any repo — 4 tools, nothing hidden

extend

.pi/extensions/*.ts         # you write the subagent/plan logic you want
pi.json                     # provider + model map (pi-ai layer)

model wiring

pi-ai multi-provider layer — BYO keys for any supported provider. No magic model pool; you choose and pay (or point local).

when to reach for it

When "75 providers" feels like liability, when you want to build the loop yourself, or as a second harness to shake loose a stalled design (the "second colleague" effect from Ch02 Beyond).

$0 path — OSS install; model still BYO (keys or local). Minimalism saves tokens, not dollars.
tip

Pi omits ceremony on purpose — read it as a thesis: every feature you add should earn its token cost. That lens is useful even when your daily driver is a heavier harness.
