First principles: what a harness decides for you

A coding agent is two things wearing one trench coat: the model — the LLM doing the reasoning — and the harness: the program wrapped around it that turns a chat into somebody who can actually touch your project. Beginners assume the model is the product. Practitioners know the harness quietly decides most of the experience. Before naming a single tool, learn the three decisions every harness makes on your behalf.

The tool loop

The harness defines which tools the model may call — read files, edit files, run shell commands, search the web — how results feed back into the conversation, how many iterations are allowed, and when the agent must stop and report. Loop design is why two harnesses driving the identical model can feel like different products: one pauses to show you a diff after every edit, another barrels through twenty steps before surfacing anything.

The permission model

Every serious harness implements some version of allow / ask / deny: actions that always run, actions that prompt you first, and actions that never run. Where those lines sit is a values decision disguised as a settings screen. A harness whose default is "skip the permission prompts" is making a philosophical statement, not a technical necessity — and you inherit it unless you push back.

Context handling

The harness decides what enters the model's attention automatically: memory files, project instructions, skill descriptions, compiler warnings. It also decides what gets compressed away when a session grows long, and whether past sessions can be resumed or branched. This silently shapes output quality long before prompt-writing skill does — Chapter 5 goes deep on it.

Four words you must be able to define

You will meet these in every harness's feature list. Learn them tool-agnostically now:

  • Skill — a written instruction file the harness loads on demand, teaching it a procedure ("how we deploy", "how we name things") only when relevant.
  • Plugin — code you add that hooks the harness's own lifecycle events, enforcing rules or adding tools the authors never imagined.
  • MCP — the Model Context Protocol, an open standard that lets a harness connect to external tool servers — databases, browsers, APIs — through one common socket.
  • LSP — the Language Server Protocol: the machinery editors use for errors and "go to definition". A harness can tap those diagnostics so the agent sees the compiler's complaints directly.

The two honest $0 doors

Money talk, briefly, because access is an on-ramp — not the subject of this book. Two doors get you working today for literally zero:

Door one: Gemini CLI's free tier. An Apache-2.0 first-party CLI whose personal-account OAuth unlocks 60 requests per minute and 1,000 per day, riding Gemini models with a 1M-token context window — the largest gratis allowance in the table.

Door two: opencode on local models. A free MIT binary that speaks to locally-running runtimes — Ollama, LM Studio, llama.cpp — so nothing leaves your machine and nothing bills you. The full map of free tiers, rate-limit math and subscription reuse is Chapter 3's job; grey-zone economics get one honest reference chapter (15). That is all the cost discussion this chapter earns.

§3

Deep dive: opencode

We go deep on exactly one harness — not because it "wins", but because its documentation is the most transparent about the $0 path and the most configurable loop. It is MIT-licensed, with roughly 201k stars and 26k forks at checking time.

Surfaces

The primary surface is a terminal UI (TUI), with a desktop app (beta), an IDE extension, and additional entry points for CLI scripting, web, GitHub and GitLab automation. Install channels: curl, npm, brew, scoop, chocolatey, pacman, docker.

Models: seventy-five-plus doors

opencode talks to 75+ LLM providers through the Vercel AI SDK and Models.dev, including local runtimes. A curated list called OpenCode Zen and a low-cost "Go" plan exist, but nobody is required to touch either.

Two built-in agents: plan and build

A build agent has full access; a plan agent is read-only. You switch with the Tab key, so "think first, touch later" is one keystroke, not a prayer. A @general subagent handles multistep searches without cluttering your main thread.

Skills and plugins

Skills are SKILL.md files in .opencode/skills directories — and they load from Claude-compatible .claude/.agents paths too, so knowledge you write travels across harnesses. They're loaded on demand, with wildcard allow/deny/ask permission rules available. Plugins are JavaScript/TypeScript files in .opencode/plugins or npm packages; they hook events like tool.execute.*, session.* and lsp.*, and custom tools can override built-ins. The Bun runtime is auto-installed to run them.

LSP: powerful, and off by default

Thirty-plus built-in language servers can feed live diagnostics straight into the agent's fix loop — yet the whole system ships disabled, flipped on with lsp: true. That is a deliberate honesty marker: the docs themselves note that simply running lint/typecheck CLIs can cost less than keeping servers synced in memory.

Sessions and safety nets

Multiple concurrent sessions (/sessions), fresh starts (/new), git-backed /undo and /redo, and opt-in /share links for showing a session to someone else. An independent write-up corroborates the multi-session, privacy-first posture.

Subscription reuse — and one grey flag

If you already pay for AI anywhere, opencode can ride it with zero setup: sign in with ChatGPT Plus/Pro OAuth, GitHub Copilot device-flow OAuth, or GitLab Duo OAuth.

grey zone · risk-flagged

Community plugins once proxied Claude Pro/Max subscriptions into opencode; they were removed in v1.3.0 because Anthropic explicitly prohibits it — treat any revival of that trick as a terms-of-service violation waiting to happen.

tip

Start with ONE harness and resist the urge to collect them. Switching later is cheap — every harness has a loop, a permission gate and memory files, so the concepts transfer even when the keybindings don't. Commit to the workflow, not the logo.

warning

This landscape moves fast and sometimes dies outright: Roo Code's extension was archived on 2026-05-15. Check the as-of date on any comparison you read — including this one — before betting a daily workflow on a row of a table.

§6

Try it yourself

  1. Install ONE door. Door A: open https://opencode.ai/docs, find Install, copy the one-line command for your OS (curl, npm, brew, scoop, chocolatey, pacman and docker are all documented), paste it into a terminal, then run the version check it suggests. Door B: open https://github.com/google-gemini/gemini-cli, copy the install command, and when prompted sign in with a personal Google account — that OAuth step is what unlocks the free tier.
  2. Run one session. In a terminal, change into any small folder, launch your harness, and give a trivial goal such as "explain what this folder contains". When a permission prompt appears, deliberately try both paths once: deny one action, allow the next. Notice what the harness asked about versus what it did silently — that gap is the permission model from earlier, made physical.
  3. Make one config tweak. opencode users: create .opencode/skills/hello/SKILL.md — start the file with the skill's name and a one-line description, add a two-line instruction — restart, and invoke it. Alternatively set lsp: true in your opencode config and restart. Before relaunching, predict what will change; after, check your prediction.
§7

Self-check

Name three decisions a harness makes for you before you've typed anything.

The tool loop (which tools exist, how many steps, when to stop), the permission model (what runs freely, what asks first, what's denied), and context handling (what loads automatically, what gets compressed away, whether sessions persist).

Which two harnesses get you working at genuinely $0 today, and through which door each?

Gemini CLI — its free tier grants 60 requests/min and 1,000/day via personal Google OAuth. opencode — a free MIT binary pointed at locally-running models (Ollama, LM Studio, llama.cpp), so no keys and no billing at all.

opencode ships 30+ LSP servers but disables them by default. Why is that defensible rather than lazy?

Diagnostics are useful but not free: keeping language servers synced costs memory and setup, and opencode's own docs note that running lint/typecheck CLIs directly can achieve similar signal for less. Defaulting off puts the tradeoff in your hands instead of hiding it.

§8

Beyond this build

When to graduate to a second harness. Three honest triggers: a problem has stalled and a differently-shaped loop shakes loose new ideas (like asking a second colleague); you need parallel capacity and would rather isolate tasks in separate tools than tangle them in one; or a specific strength matters that day — Aider's git-native auto-commits, Codex CLI handing the same agent its cloud twin, Goose's embeddable Rust API. Owning two harnesses isn't disloyalty; the workflow is the asset, and it ports.

IDE versus terminal versus desktop. Editor-integrated agents (Cline, opencode's extension, Gemini's VS Code companion) put diffs next to your code and feel familiar fastest. Terminals script well, ssh into remote boxes, and chain into pipelines; they reward fluency with fewer clicks per iteration. Desktop apps (Claude Code, Goose, opencode's beta) split the difference with visual session management. Match the surface to the task; none demands an exclusive marriage.

Where each one breaks. opencode: breadth means more configuration before the magic, and npm plugins execute code at startup — vet them like any dependency. Claude Code: proprietary with no free tier, and its ecosystem assumes its own memory formats. Codex CLI and Gemini CLI shine brightest inside their maker's accounts and models — less neutral ground. Cline is happiest where VS Code or JetBrains live. Aider trades autonomy for a pair-programming rhythm. Goose carries younger governance after the Block-to-AAIF handoff. Cursor CLI's licensing and free limits were unverified at print time — check before committing. Pi omits subagents and plan mode on purpose: ceremony is yours to build. And Roo Code is the standing reminder that every row above has an expiry date.
