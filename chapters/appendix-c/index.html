A

3 terms↑ top

agent

/ˈeɪ.dʒənt/ · nouncore

A program that runs a language model in a loop, toward a goal, with tools — and stops when a check says it is done.

You set the goal and the stopping check (“these three tests pass, no other files touched”). The harness feeds the model tools — read, edit, run — and the model chooses the next tool, sees the result, tries again. That loop is the “agentic” part; without it, you have a chatbot that answers once and waits.

why it matters → If you cannot state the stopping check, you cannot verify the agent and should not delegate. Aim → watch → verify is your job; typing is the loop's.
see also: harness loop workflow Ch 01Ch 06

agentic loop

core

The machine's inner loop (thought → tool → observation → evaluate) wrapped by your outer loop (aim → watch → verify → commit).

Inside, the model predicts the next action from the transcript. Outside, you own the goal, the plan scan, and the proof you run yourself. The craft of the book is shaping what the inner loop sees and what may stop it.

why it matters → Confusing the two loops is how “looks done” ships. Give the inner loop a check it can run; keep the outer check human.
agent verification loop Ch 01Ch 06

allowlist / deny list

safety

Explicit lists of tools or actions the harness may do without asking, must ask about, or must never do.

Example: allow npm run lint, ask before git push, deny any write to .env or migrations/. Wildcards like allow / ask / deny per skill keep the rule in code, not just prose.

why it matters → Advisory text gets ignored; deny lists are deterministic guardrails. “Skip approvals” outside a disposable sandbox is radioactive.
permission gate hook Ch 04Ch 14

B

5 terms↑ top

batch / fan-out

core

Running many independent agent invocations in parallel — one per file or task — instead of one long session.

Pattern: write the file list, loop claude -p or subagents with a narrow prompt and scoped --allowedTools, then collect OK/FAIL. The book uses it for migrations and adversarial reviews.

why it matters → Keeps each context small and failures isolated. Use scoped tool lists when running unattended — never batch with full permissions.
subagent worktree Ch 06Ch 13

bisection

core

Halving the search space to find the breaking change — “did it fail halfway here?” repeated until one commit or line remains.

Automated with git bisect or a script that returns pass/fail. Faster than linear scanning and forces you to define the failure precisely.

why it matters → When an agent “fixes forward” in circles, bisect pins the regressor so you stop guessing and start measuring.
evals-lite Ch 10

bloat · anti-bloat

shipping

Bloat is code, deps or process that adds cost without capability; anti-bloat is the habit that prevents it.

Agents add artifacts quickly. Anti-bloat means CI build caps, dep hygiene, quiet seasons where the “full net” costs more than it catches, and a refactor trigger before complexity exceeds steering.

why it matters → Shipping is not the end of growth — unchecked scaffolding is how side projects die. Track debt explicitly.
CI gate Ch 11Ch 12

brownfield

shipping

An existing, lived-in codebase you must change without rewriting — the opposite of greenfield.

Work is understand-before-edit: map the repo, branch before you brief, make the smallest edit the tests allow, and verify against the old behavior.

why it matters → Most paid work is brownfield. The costliest agent mistake is an unmapped big edit that looks plausible and breaks invariants you never read.
Ch 11

threaded build

shipping

One of three projects built chapter-by-chapter through the whole book — the practical spine, never the scope.

Build 1 Agent Cost Compass (weekend) · Build 2 NCERT Quiz Forge (two-week) · Build 3 Free-Tier Atlas (six-week capstone). Each <$0, each shipped; lessons generalize in “Beyond this build.”

why it matters → Techniques land on real code, not toys. If you reuse the workflow, swap the domain — keep the discipline.

C

9 terms↑ top

checkpoint / rewind

context

A snapshot of conversation + files you can restore to, instead of nursing a broken session forward.

In Claude Code, every prompt creates a checkpoint: Esc Esc or /rewind can restore conversation, code, or both, or summarize from a point. Use it to try risky moves fearlessly.

why it matters → Do not compound a bad approach in one transcript. Rewind is cheaper than convincing a polluted context.
compaction Ch 05Ch 16

CI gate

shipping

An automated check that must pass before code merges — build, lint, typecheck, tests, or a deterministic script.

Give the agent a gate it can run locally, not just in CI. The gate is the “deterministic proof” the agent iterates against; you review evidence, not assertions.

why it matters → Without a gate you are the verification loop. With one, you watch evidence scroll by and walk away.
verification loop hook Ch 12

compaction

context

Summarizing the middle of a long transcript to free the context window, while keeping key decisions and file states.

Automatic compaction triggers near the limit; /compact Focus on … or /rewind → Summarize from here gives you control. In prose you can also instruct compaction to preserve the modified-files list and test commands.

why it matters → Performance degrades as context fills. Compact early, or /clear between unrelated tasks — rescue is worse than restart.
context window context rot Ch 05

context engineering

context

Deliberately choosing what the model sees — and what it never sees — so the loop stays steerable.

Not “prompt engineering” word games. It is file selection, instruction budgets, repo maps instead of dumps, and token discipline. Everything in the transcript is context.

why it matters → Context is the scarcest resource. Curating it is higher leverage than phrasing the prompt.
Ch 05

context rot

context

Gradual loss of performance as irrelevant or stale text accumulates in the window.

The model “forgets” early instructions and makes more mistakes. Causes: kitchen-sink sessions, over-long instruction files, re-reading solved files. Fixes: /clear, subagents, compaction, short memory files.

why it matters → If a second correction fails, the transcript is probably the bug. Restart clean with a better prompt.
compaction subagent Ch 05

context window

context

The total text — conversation, file reads, tool output — the model can see at once, measured in tokens.

Ranges from tens of thousands to over a million tokens by model. A single long debug trace can consume it. The window is the book's central constraint: “performance degrades as it fills” is the law every pattern obeys.

why it matters → Treat tokens as budget. Use subagents for research and /clear between tasks so the main thread stays lean.
token compaction Ch 05

coverage matrix

core

A table proving every important dimension of agentic coding gets at least one chapter.

Rows = dimensions (harness choice, MCP, hooks, brownfield, security …), columns = chapters. If a row has no check, scope is missing. The book ships it as Appendix D.

why it matters → It keeps a growing book honest — you can audit “have we taught this?” without trusting the table of contents.
App B

CLI tool

tools

A command-line program you teach the agent to call — gh, aws, sentry-cli — instead of hand-using APIs.

Agents learn new CLIs via --help faster than they parse docs. Use them for GitHub, cloud, or any external service — they are the most token-efficient integration.

why it matters → Without gh, API calls hit rate limits and churn. With it, issues and PRs become one-liners.
MCP Ch 02

CLAUDE.md / AGENTS.md

context

A short, human-readable memory file the harness loads every session — commands, style, and rules the model cannot infer from code.

AGENTS.md is the open standard (Linux Foundation); CLAUDE.md is the Claude Code equivalent. Keep it short, nearest file wins, and prune anything the agent already does right. For occasional knowledge, prefer skills.

why it matters → Good memory compounds; bloated memory poisons. Test every line by removing it and watching behavior shift.
skill context rot Ch 04

D

1 term↑ top

deterministic gate

safety

A rule enforced by code that always runs — not by text the model may ignore.

Prose in CLAUDE.md is advisory (“please run tests”). A hook is deterministic (“block the turn until npm run lint exits 0”). For must-happen checks, make them hooks, not wishes.

why it matters → The longest instruction file is still weaker than one script that refuses to let the turn end.
hook CI gate Ch 04

E

2 terms↑ top

evals / evals-lite

shipping

A repeatable check — tests, build, or screenshot diff — that returns pass/fail for what the agent built.

“Evals” is the full suite; “evals-lite” is the cheap smoke test you run every loop. The opposite of “looks done” — evidence over assertion.

why it matters → Without an eval you are the verification loop. With one, the agent self-corrects and you audit evidence.
verification loop Ch 09

evaluator / gauntlet

core

A second, fresh-context agent that judges the first agent's output against a bar — blind, harsh, and without loyalty to the draft.

The book's quality loop: builder → critic (fetches real bars, compares blind, names the biggest gap) → builder again, until the critic picks “ours” without knowing which is which. A cheap proxy for human review.

why it matters → Fresh context beats self-review. If the evaluator flags only style, you are over-engineering — gate on correctness.
gauntlet Ch 06

F

2 terms↑ top

free tier

shipping

A provider's no-billing allowance — e.g. 60 req/min, 1 000 req/day — before rate limits or paywalls.

Gemini CLI's OAuth quota is the book's honest $0 door; others show limits per-project. Free tiers move without notice — re-fetch before you bet a workflow.

why it matters → Know the wall before you hit it. Drag usage against limits and watch 429s move, rather than discovering them at demo time.
rate limit Ch 03

framing · nested instructions

context

How instruction files compose: nearest file wins, parents are background — so scope rules, not slogans.

Put project rules at the root, tighter rules beside the code they govern. The loader shows precedence visually when you toggle files on.

why it matters → Without nesting, one long global file contradicts itself by line 40 and gets ignored.
CLAUDE.md Ch 04

G

2 terms↑ top

gauntlet loop

core

Builder → fresh-context harsh critic → biggest gap → rebuild, looping until “ours” wins blind against a real bar.

Visual bar (ciechanow.ski) and content bar (Anthropic best practices) are fetched live, labels stripped, and judged binary. Never exit on a round count — only when the critic picks us.

why it matters → Taste without a comparator drifts. A blind comparator keeps taste honest.
evaluator Ch 06

grey zone

safety

A trick that works today but violates a provider's terms, relies on an unofficial proxy, or risks account or data loss.

In this book, grey zones are never recommended without a red-bordered warning naming what it is, why people do it, what breaks, and what it could cost. Example: Claude Pro/Max proxies removed in v1.3.0.

why it matters → You deserve to know what exists and why not to bet on it. Flagged grey zones protect your semester and your billing account.
rate limit Ch 15

H

2 terms↑ top

harness

tools

The program wrapped around the language model — invisible prompts, tools, permissions, transcript memory — that turns text prediction into action.

Same model through different harnesses feels like a different product. The harness decides what the model may read, write, run, and remember. Examples: opencode, Claude Code, Gemini CLI, Aider, Goose.

why it matters → Pick the harness for its tools and gates, not its logo. Switching later is cheap; the loop ports.
agent model Ch 01Ch 02App A

hook

tools

A small script the harness runs automatically at a lifecycle point — e.g. before edit or at turn end — that can block progress until a check passes.

In Claude Code, a Stop hook can gate “turn may not end until tests pass” (8-block cap before fallback). Unlike prose, hooks are deterministic — zero exceptions.

why it matters → For must-happen checks, write a hook. Text nags; hooks enforce.
deterministic gate Ch 04

I

2 terms↑ top

infinite wander

core

The loop re-reads the same files and tries near-identical fixes without converging — the signal of a vague goal.

Signature: growing diff, same errors, slow tools stalling. Fix is human: timebox, narrow the goal, restart clean. A thrash detector can flag it automatically.

why it matters → Nursing a doomed session burns context. Kill it and restart with a falsifiable stopping check.
kitchen-sink Ch 10

instruction file

context

A markdown rule file that configures the agent — AGENTS.md or CLAUDE.md — with nested precedence (nearest wins).

Loaded every session; keep it short or rules get ignored. Put broad rules at the repo root, tighter rules beside the code they protect. Prefer skills for occasional knowledge.

why it matters → One bloated file contradicts itself. Nearest-wins keeps scope honest.
CLAUDE.md Ch 04

K

1 term↑ top

kitchen-sink session

core

One endless conversation holding five different goals — it fills context, contradicts itself, and produces an unreadable diff.

The canonical beginner failure. The cure is ritual: one goal per session, /clear between unrelated asks, and treating a fresh start as cheap.

why it matters → Rescuing a bloated thread almost never beats restarting with a sharper goal.
context rot Ch 01

L

3 terms↑ top

local inference

shipping

Running a model on your own machine — via Ollama, LM Studio, or llama.cpp — so nothing leaves the box.

Trades raw capability for privacy, zero marginal cost, and no rate walls. The book's <$0 pair is opencode + Ollama or Gemini CLI's free OAuth — pick one door, not a collection.

why it matters → When data cannot leave or quotas are tapped, local is the pressure valve.
subscription reuse Ch 03

loop

core

The predict → act → observe → evaluate cycle that makes a session “agentic.”

Short for the agentic loop. Each pass predicts one tool call from the transcript. Craft is what you let in, what you block, and when you declare success.

why it matters → Name the loop and you can shape it — add a check, scope a permission, clear context before it clutters.
Ch 01

LSP

Language Server Protocoltools

A background checker that feeds compiler/linter diagnostics to the agent so it can fix its own edits.

30+ servers exist; in opencode they are off by default — lsp: true opts in. Prefer lint CLIs when cheaper than the token cost of live diagnostics.

why it matters → Immediate diagnostics close the loop faster, but only if the signal is worth its context cost.
Ch 02

M

3 terms↑ top

MCP

Model Context Protocoltools

A standard for plugging external tools and data — files, databases, design canvases — into the agent as callable tools.

MCP servers expose functions the model can invoke; 70+ exist for Goose alone. Treat every MCP as code with supply-chain risk — vet sources like any dependency.

why it matters → MCP is how the agent reaches beyond the repo. Every server is a permission and a liability.
tool hook Ch 02Ch 14

model

core

The language model itself — a system that predicts likely next text, one token at a time, with no hands of its own.

It cannot open a file or remember yesterday until a harness gives it tools and transcript memory. Two harnesses with the same model behave very differently — the harness is most of the product you feel.

why it matters → Fixating on model names hides leverage. Fix the harness, the context, and the check first; swap models last.
harness token Ch 01

memory (cross-session)

context

Information that survives after the transcript ends — typically a short memory file you curate between sessions.

The model itself forgets; the harness reloads your memory file next time. Keep memory distillable: what went wrong, what the project is, what “done” means.

why it matters → Without cross-session memory every session re-learns the same lessons at token cost and risk of drift.

O

1 term↑ top

open-weight

shipping

A model whose weights you can download and run — you host it, you pay for compute, you owe nothing per token.

Opposite of API-only. Often paired with local runtimes or cheap hosts like Groq, Cerebras, or OpenRouter. Capability varies by size and hosting.

why it matters → Open-weight is the <$0 escape hatch when API quotas or costs block you — trade capability for control.
local inference Ch 03

P

6 terms↑ top

permission gate

safety

The harness asking (or refusing) before edits or commands land — plan (read-only) vs build (full access).

In opencode: Tab flips plan ↔ build. In Claude Code: plan mode via Shift+Tab. The gate is the cheapest safety you have — keep it closed until you have scoped the change.

why it matters → Every scary demo is a gate opened too early. Scope first, write second.
allowlist plan mode Ch 02

plan mode

tools

A read-only mode where the agent explores and proposes a plan — no writes — before it may implement.

Use when the change spans files or you are unfamiliar. When the fix is one sentence long, skip the plan and implement directly.

why it matters → Planning prevents solving the wrong problem. Review the plan's scope before you approve code.
Ch 04

plugin

tools

Code that extends the harness at startup — typically JS/TS from .opencode/plugins or npm — with access to lifecycle hooks.

Plugins can override tools and run on every session. Treat them like dependencies: vet, pin, and audit startup code.

why it matters → Convenience that runs at boot is supply-chain surface. Cheap to add, slow to audit after it lands.
skill hook Ch 04

prompt injection

safety

Tricking the agent into following instructions from untrusted content it read — an issue, a web page, a file — instead of your intent.

An agent with shell access that reads adversary-controlled text is an injection target by construction. Sandbox, scope tool use, and never auto-approve reads of unknown origin.

why it matters → Autonomy + network + shell = vulnerability. Every “read the web for me” is an injection gate.
sandbox Ch 14

provider

shipping

A company or gateway that serves a model via an API — e.g. Anthropic, OpenAI, Groq, or an aggregator.

Some harnesses route through 75+ providers (opencode via Vercel AI SDK + Models.dev). The book teaches the concept, not the logo — wiring changes monthly.

why it matters → Knowing the provider layer keeps you portable — switch providers without rewriting prompts.

4 terms↑ top

rate limit · 429

safety

A cap on how often you may call the model — requests per minute/day, tokens per minute — enforced with HTTP 429 “retry after.”

Free tiers set low walls; paid tiers lift them. The limit-feeler widget in Ch 03 drags usage against moving walls so you see the 429 before production does.

why it matters → Unplanned 429s break demos and capstone builds. Budget requests like you budget tokens.
free tier spend cap Ch 03

receipt

core

A source card attached to a claim — URL + tier badge + as-of date — so any reader can re-check you in minutes.

T1 official/practitioner carries; T2 vendor/press is flagged as marketing; T3 lead-only never stands alone. The ledger in Appendix B is the book's receipts machine.

why it matters → “Trust me” does not survive week two. Receipts make revisiting and refuting cheap.

sandbox

safety

OS-level isolation that restricts what the agent can read, write, or reach on the network — even if the prompt is tricked.

Complements allowlists. Let sandboxed commands run without prompts; keep manual approval for anything that escapes the box.

why it matters → Injection payloads need a shell to hurt you. A sandbox removes the shell from the blast radius.
permission gate Ch 14

skill

tools

A markdown file (SKILL.md) that teaches the agent a reusable capability — loaded on demand, not baked into every session.

Lives in .opencode/skills/*/SKILL.md or .claude/skills/. Example: “frontend-design” with tokens and component contracts. Wildcard permissions travel with the skill.

why it matters → Skills prevent memory bloat: keep broad prose thin, and load deep knowledge only when the task calls for it.
plugin CLAUDE.md Ch 04

slash command

tools

A typed command like /compact, /clear, or /review that triggers a built-in harness action.

Often faster than natural language for session control. Skills may expose their workflows as slash commands too.

why it matters → One prefix keeps control explicit — ask with prose, act with commands.

core

App B

spend cap

safety

A hard budget ceiling — tokens or money — that stops the agent instead of overrunning silently.

Some consoles support “free-quota-only” mode that returns 403 instead of charging. Set caps per session and per month; pair with rate-limit budgeting.

why it matters → Without a cap, “iterate until it passes” can iterate until your card is empty.
rate limit Ch 15

subagent

tools

A delegated agent that runs in its own context window and returns a summary — so research does not bloat your main transcript.

Invoked for investigation or adversarial review. Because its context is isolated, it “forgets” your draft loyalties and judges fresh.

why it matters → Context is scarce. Subagents keep the main window lean and make parallel investigation cheap.
fan-out evaluator Ch 06

subscription reuse

shipping

Pointing the harness at a subscription you already pay for — ChatGPT, Copilot, GitLab Duo — instead of buying API credits.

In opencode: ChatGPT OAuth or Copilot device-flow “zero setup.” Honest $0 for students who already have the sub; grey-zone proxies are excluded since v1.3.0.

why it matters → Cheapest honest path after local and Gemini's free tier — no billing page involved.

T

4 terms↑ top

TDD with agents

shipping

Writing the test (or eval) before the agent writes the code — so the loop has a proof to chase from the first pass.

Pattern: “cases: … — run the tests after implementing.” The check is the stopping signal; without it you are the oracle.

why it matters → Tests turn “looks done” into “passes.” Give the agent the cases and let it iterate.
evals Ch 09

token

context

The small chunk of text — roughly ¾ of a word — that the model counts and charges by.

“Tokens in / tokens out” drive price tables and the context-window budget. Cached-input and off-peak discounts price tokens differently by provider.

why it matters → Token math is money math. Know your pattern (in/out split) before you pick a provider.
context window Ch 05

tool

tools

Any callable function you expose to the model — read a file, edit, run a command, query an MCP server.

In Pi the core is four tools (read/write/edit/bash); other harnesses offer dozens. More tools is not more capability — it is more surface to guard.

why it matters → Curate tools like you curate context: fewer, well-scoped tools make safer, cheaper loops.
MCP Ch 01

trust-then-verify gap

core

The failure where output reads plausibly so nobody reads the diff or runs the proof — and a subtle break merges.

Diagnosis: accountability stays human even when tooling implies otherwise. Fix: a verify ritual you never skip.

why it matters → Plausible is the most dangerous quality level — almost correct is hardest to catch.
kitchen-sink Ch 01

V

2 terms↑ top

verification loop

core

The pattern “give the agent a check it can run” — tests, build, linter, or screenshot diff — so it iterates without you.

Without a check, “looks done” is the only stop signal and you become the verification loop. Ladder: in-prompt (“run tests and iterate”) → /goal → Stop hook → fresh-context subagent reviewer.

why it matters → A loop without a verifier is a wander. A loop with a verifier can finish while you walk away.
evals hook Ch 06

vibe coding / agentic engineering

core

Vibe coding is “accept all, read nothing” for throwaway fun; agentic engineering is orchestrating agents with oversight and no quality compromise.

The former is the coined exception; the latter is the book's standard: aim with a stopping check, supervise, verify, commit only what you can explain.

why it matters → Vocabulary sets expectations. Call the work what it is, and the review bar stays human.
Ch 01

W

2 terms↑ top

workflow (vs agent)

core

Code orchestrating a model through fixed steps you already understand — the simpler, cheaper, more predictable alternative to a fully autonomous agent.

Workflow = human designs the process, model fills the slots. Agent = model designs the process, choosing tools on the fly. Guidance: “start with the simplest thing that could work; add agent flexibility only when measurements say you must.”

why it matters → Flexibility costs latency, tokens, and compounding errors. Prefer workflows until open-ended search is genuinely needed.
agent Ch 01

worktree

shipping

A second, isolated checkout of the same repo — so two agents (or you + agent) can work in parallel without colliding.

Created with git worktree. Each worktree is a separate directory sharing one history; paired with batch fan-out for scale and with ritual (ch16) for daily hygiene.

why it matters → Parallelism without worktrees is a race on the same files; worktrees make it a branch, not a brawl.
